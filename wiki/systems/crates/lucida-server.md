# lucida-server

Tokio + Axum WebSocket relay. Brokers multi-client sessions, sequences shared document commands, broadcasts presence, opens datasets via [lucida-store](lucida-store.md), serves source chunks from a `CachedStore`, and generates/serves derived coarse chunks through the same chunk path. The retired proxy/asset fallback was deleted under [ADR-0043](../../decisions/0043-superseded-server-surfaces-sunset.md); coarse/detail source or generated pyramid levels are the only residency path. Per [Single-Image Container with `ServeDir` is the Canonical Deploy Unit](../../decisions/0020-single-image-with-servedir.md) it also serves the SPA bundle directly via `tower-http::ServeDir`, so the production deploy unit can be a single container image and a developer's local `:9876` can render the app without an extra reverse proxy.

## Why a relay, not a peer-mesh

Lucida is collaborative: many viewers can see the same dataset and follow each other. The server exists for two reasons:

1. **Document-state arbitration.** Each `DocumentCommand` (e.g. `DatasetOpened`) gets a monotonically increasing `seq` and an `Ack` to the sender. New clients receive a `Snapshot` of the full document state on connect. This makes "what datasets are loaded" a single authoritative fact.
2. **Storage proxy and chunk router.** Browsers can't realistically open arbitrary `gs://` / `s3://` Zarr stores directly with credentials. The server probes the store, builds a [DatasetManifest](lucida-content.md), and on demand fetches/decodes source chunks or generated coarse chunks and forwards them as binary frames to the requesting client. The bytes the client sees are pre-decompressed (Lz4/Zstd → raw for source chunks), keyed by `(dataset_id, image_id, chunk_key)`.

Presence (cursor, viewport, follow) doesn't need arbitration — it's broadcast through the same WebSocket but never sequenced or persisted. See [Document vs Viewport Command Split](../../decisions/0001-document-vs-viewport-split.md).

## Module map

- `lib.rs` — `AppState`, `BroadcastItem` (the in-process pub/sub envelope), `DatasetRuntimeConfig`
- `main.rs` — Axum server entry point; wires WebSocket handler, admin routes, and the two-router split for [Authentication](../subsystems/auth.md)
- `handler.rs` — per-client connection loop: snapshot → broadcast subscribe → inbound dispatch (`ClientMessage` / `ChunkMessage::ChunkRequest`), source/generated chunk-frame serving, dataset health snapshots, and the thin websocket adapter for dataset open (parse the message, call `dataset_open::open_dataset`, forward its progress + terminal diagnostics to the requesting client). Client-originated binary frames fail closed. Contains **no authorization checks** — workspace command authority lives in the `WorkspaceManager` (see the invariant below)
- `dataset_open.rs` — headless dataset-open orchestration (`open_dataset`): URL normalize → authorize (via `WorkspaceManager::require_editor`) → persisted-source lookup → dedup / concurrent-open race handling → backend probe → metadata import → binding + generated-service build → document apply + workspace persist + `DatasetOpened` broadcast. Per-stage `DatasetOpenProgressDiagnostic`s flow out through an `mpsc` progress channel and the terminal result is a typed `DatasetOpenOutcome` / `DatasetOpenFailureDiagnostic`, so the whole use case runs (and unit-tests) with zero websocket types. Imports the workspace layer one-directionally; nothing under `workspace/` imports it back
- `binding_restore.rs` — rebuilds server-private `ServerBinding`s for a lazily reopened workspace from its persisted `workspace_datasets → dataset_sources` rows; called by `WorkspaceManager::live_workspace` on wake, before the live session is published (its background-fill enqueue is therefore awaited inline — nothing is waiting on a reply there, unlike the interactive open, which spawns that step). Depends only on `workspace/types.rs`, never the manager, so the manager can call it without an import cycle
- `open_diagnostics.rs` — leaf classification of storage/import errors into the `DatasetOpenFailureDiagnostic` stage/kind/retryable vocabulary, shared by `dataset_open.rs`, `binding_restore.rs`, and the handler's own denial messages so every path triages the same error identically; these shapes are wire-visible (the fixtures pin them)
- `session.rs` — `Session` state: `DocumentState` + history ring buffer + per-client `PresenceState` + `server_bindings: HashMap<DatasetId, ServerBinding>`
- `binding.rs` — `ServerBinding`, `ChunkResolver`; consumes the already-detected `StorageCompression` (detection lives in [lucida-store](lucida-store.md)'s `codec::parse_codec_chain`, an import-time validator)
- `decode.rs` — Lz4/Zstd/Blosc → raw decode (`DecodeError::Lz4`/`Zstd`/`Blosc`, Blosc in the `decode/blosc.rs` submodule), shared between source chunk serving and derived generation
- `health.rs` — unauth public router: `/healthz` (liveness), `/readyz` (readiness), `/version`, for containerized deploys (kubelet probes carry no session cookie)
- `legacy_bookmark_recovery.rs` — offline, dry-run-first recovery from retired global bookmark rows into one chosen workspace; owns strict source-identity matching, complete dataset-id remapping, URL stripping, credential-safe plan/error output, a stable one-document `--json` failure contract, and atomic persistence for the `recover-legacy-bookmark` operator command
- `source_identity_migration.rs` — startup data migration for the released short dataset-source ids that SQLite cannot rekey declaratively (BLAKE3 is computed in Rust). It validates the complete source/reference graph before writing, rejects identity collapse instead of guessing how to merge memberships, atomically canonicalizes locator spellings and moves source FKs to full identities, preserves every `wds-*` id, shares the explicit legacy-id aliases with bookmark recovery, and emits only typed reason codes plus the shared credential-safe source diagnostic when startup fails
- `generated_coarse/` — hand-written generated-coarse implementation, split by responsibility: planning, scheduling/cancellation, materialization math, derived-cache persistence/recovery, and availability broadcasting
- `auth/` — Google OAuth + session cookies + admin allowlist + cleanup sweep + audit logging. See [Authentication](../subsystems/auth.md) for the deep-dive.
- `workspace/` — workspace records, membership/link sharing, archive/restore lifecycle, authorization, lazy live-session restore, workspace-scoped document persistence (annotations live in `DocumentState`, so an `AddAnnotation` command is persisted via `persist_document` and broadcast over the session like any other document command), explicit workspace admin support routes under `/admin/workspaces/*`, and REST/WebSocket routes under `/api/workspaces/*` and `/ws/workspaces/:id`. Its layers are `types.rs` (role/link-access/saved-view-visibility enums + record/summary structs), `store/` (`WorkspaceStore` trait in `mod.rs`, the production `SqliteWorkspaceStore` + row mappers in `sqlite.rs`), `manager.rs` (`LiveWorkspace` + `WorkspaceManager` runtime, authorization — including the editor gates for workspace-scoped WS document commands: `apply_document_command`, `rename_dataset`, `dataset_source_for_retry` — `WorkspaceError` + HTTP mapping), `http.rs` (DTOs, handlers, `router` builder), and `tests/` (the workspace unit/route tests, grouped by behavior area — access/lifecycle, saved views, datasets, duplicate — with shared fixtures in `tests/mod.rs`). `mod.rs` re-exports the public names, so callers keep using `workspace::{WorkspaceManager, router, ...}` paths.
- `browse.rs` / `admin.rs` — HTTP routes for filesystem browsing and admin operations. The compatibility-named `clear-proxy-cache` route/subcommand clears the active generated-coarse cache, process source cache, and the separately configured retired proxy-era root during upgrades. There is no live proxy cache and no new write targets `LUCIDA_PROXY_CACHE_DIR`. `browse_handler`'s `path` query param is optional per [Canonical dataset URL form](../../decisions/0042-canonical-dataset-url-form.md). Returned paths use canonical display form and the configured local-root security boundary remains enforced.
- `migrations/` (crate root, `lucida-server/migrations/`, not under `src/`) — versioned SQL migrations applied at startup (sqlx). Active persistent state includes [Authentication](../subsystems/auth.md) (`login_sessions`, `pending_auth`, plus `bearer_tokens` and `cli_token_authorizations` for non-cookie credentials) and workspaces (`workspaces`, `workspace_members`, `dataset_sources`, `workspace_datasets`, `workspace_saved_views`, `user_workspace_state`, `workspace_viewer_profiles`). `lucida_data_migrations` records computed data upgrades that SQL cannot perform; schema migration completes first, then the source-identity upgrader validates/rekeys in its own transaction before startup continues. The retired `bookmarks` + `bookmark_datasets` migrations remain in the immutable ledger and leave existing rows inert; the dry-run-first [`recover-legacy-bookmark`](../subsystems/saved-views.md#recovering-a-retired-bookmark) command is the supported path into `workspace_saved_views`.
- `static_serve.rs` — SPA-asset router built around `tower-http::ServeDir`. `main.rs` reads `LUCIDA_WEB_DIST` (default `./lucida-web/dist`) and passes the resolved path in; this module only names the env var in its build-instructions landing-page text. Serves the bundle with index-fallback for client-routed deep links, or that landing page when the dist dir is missing. Mounted on the **public** router half (no auth wrap) so HTML/JS/CSS aren't 401'd; auth gates remain on `/auth/whoami` polling and `/api/*`. See [Single-Image Container with `ServeDir` is the Canonical Deploy Unit](../../decisions/0020-single-image-with-servedir.md).

## Interactions

- **Inputs from clients**: `ClientMessage` (commands, presence, cursor, follow, dataset-open requests) and `ChunkMessage::ChunkRequest`. Client-originated binary frames and retired asset/chunk-fetch variants are rejected rather than relayed.
- **Outputs to clients**: `ServerMessage` (snapshot, broadcasts, peer events, dataset-open diagnostics, generated availability/status, source status) and the canonical binary chunk frame owned by [lucida-protocol](lucida-protocol.md).
- **Auth gate**: every non-`/auth/*` route runs through middleware that extracts an `AuthPrincipal` from the `lucida_session` cookie. Public routes (`/auth/start`, `/auth/callback`, `/auth/error`, `/auth/dev/login` in dev) live in a separate router half. See [Authentication](../subsystems/auth.md).
- **Dependencies**: [lucida-core](lucida-core.md) for the Scene/document model, [lucida-content](lucida-content.md) for `DatasetManifest`, [lucida-protocol](lucida-protocol.md) for wire types/codecs, and [lucida-store](lucida-store.md) for storage backends and import. `object_store` provides cloud abstraction; `axum`/`tokio` the network stack; `sqlx`, `jsonwebtoken`, and `reqwest` persistence/auth.

## Workspace Admin Support

The v0 support surface is intentionally API-only and explicit. Lucida admins use `/admin/workspaces` routes rather than a broad admin dashboard:

- `GET /admin/workspaces?q=<text>&include_archived=true&limit=25` searches by workspace id/name, creator email, or member email and returns limited metadata, member count, owner count, dataset count, link settings, and archive state.
- `GET /admin/workspaces/:id` returns the same metadata plus ordered member summaries without adding the admin as a workspace member.
- `POST /admin/workspaces/:id/archive` and `POST /admin/workspaces/:id/restore` use the normal archive/restore storage path; archive also broadcasts `workspace_archived` and drops the live workspace.
- `POST /admin/workspaces/:id/owners` with `{"email":"user@example.com","display_name":"User"}` adds or promotes an owner, including for archived or orphaned workspaces. It never removes or demotes owners, so the normal last-owner invariant remains intact.

## Invariants

- **Document commands are sequenced and acked; presence updates are not.** Sender of a command receives `ServerMessage::Ack`; everyone else receives `ServerMessage::CommandBroadcast`. Both carry the same `seq`.
- **Broadcast overflow is repaired with a fresh snapshot, not just logged.** The per-client outbound loop forwards a bounded broadcast channel; when a slow client's receiver hits `RecvError::Lagged` the loop pushes it a fresh `Session::snapshot` (taken under the session lock *after* the receiver has been repositioned past the loss, so the snapshot's `seq` covers every skipped message and no hole can open before the resume point). The client detects loss independently — a `seq` gap in the `CommandBroadcast`/`Ack` stream that persists past a short reorder-grace window (a gap alone is NOT loss: broadcasts are sent after the session lock is released, so concurrent editors deliver out of order routinely) — and sends `ClientMessage::RequestSnapshot`, answered on its unicast channel with the same fresh-snapshot construction, throttled to one served request per second per client (serving one clones the whole document under the session lock). The client's seq discipline (stale-drop after resync, buffered tail, the membership-gated `dataset_opened` dedup-rebroadcast exception, unacked-command replay after full-replace) is in [Flow: Document Command Application](../../flows/document-command-application.md). Locked by `tests/lagged_resync_e2e.rs` over real workspace WebSockets.
- **Workspace command authorization is enforced in `WorkspaceManager`, never in the websocket adapter.** Generic document commands go through `WorkspaceManager::apply_document_command` (editor gate → apply → persist), renames through `rename_dataset`, dataset retry through `dataset_source_for_retry`, and dataset open through `dataset_open::open_dataset`'s authorization stage (`require_editor`) — `handler.rs` only translates the manager's verdict into wire messages and contains no `require_*` calls. The gate's failure modes stay distinct end to end: a role that denies is Forbidden, while a role lookup that *errors* is `CommandApplyError::GateUnavailable` (command apply) or a retryable `WorkspaceLookup` diagnostic (dataset retry) — a transient store failure is never presented as an authorization verdict.
- **Workspace access is resolved by explicit membership before link access.** Owners manage members and link settings. Explicit members may be viewer/editor/owner; anyone-with-link may grant viewer/editor only. Link-shared workspaces are openable by URL but are not globally listed for every signed-in user.
- **Workspace recents and pins are personal state.** `user_workspace_state` records a principal's last-opened timestamp and personal pin. It does not grant access; list APIs only include link-derived state while the workspace still allows anyone-with-link access.
- **Archived workspaces are durable but inaccessible.** Archive sets `workspaces.archived_at`, removes the workspace from normal lists, denies new HTTP/WS opens, denies document mutations via the normal role checks, and broadcasts `workspace_archived` to connected clients before dropping the live workspace from the manager map. Restore clears `archived_at`; it does not delete or recreate document, dataset, member, saved-view, or user-state rows.
- **Live workspace eviction only drops runtime state.** `LUCIDA_WORKSPACE_IDLE_TTL_SECS` (default 3600) and `LUCIDA_WORKSPACE_IDLE_SWEEP_SECS` (default 60) control idle live-workspace cleanup. Eviction requires zero connected clients, cancels workspace-scoped background mutation paths, shuts down generated-coarse workers, and removes only the in-memory `LiveWorkspace`; SQLite rows and generated-coarse cache remain reusable on lazy reopen.
- **Dataset source identity and workspace layer identity are split.** Workspace sessions use a random opaque workspace-local `DatasetId` (`wds-*`) in document/runtime state, while `dataset_source_id` remains URL-derived for source membership dedupe and generated/cache reuse across workspaces. The source helpers (`dataset_id_for_url`, `dataset_url_hash16`) live in [lucida-content](lucida-content.md)'s `url` module per [Canonical dataset URL form](../../decisions/0042-canonical-dataset-url-form.md); a source identity is not a live layer id.
- **Dataset open sends the full payload exactly once to the requester.** The requester receives `OpenDatasetSucceeded` with the compatibility `opened` payload plus the compact summary; the peer `CommandBroadcast` excludes that socket. Peers still receive the sequenced `DatasetOpened` command.
- **Self-presence is filtered server-side.** The outbound loop checks `sender == id` and drops presence/cursor/peer-joined messages back to their originator. Only `CommandBroadcast` is rewritten to `Ack` for the sender; everything else is silently filtered.
- **Per-client delivery and request work are bounded.** The byte-and-message-budgeted `Outbox` carries targeted chunk/status traffic; each connection has a 32-task ceiling and each authenticated principal shares a 64-permit semaphore. Disconnect aborts and awaits outstanding tasks so permits are returned deterministically. The canonical binary codec validates client-id and key-length narrowing before constructing a frame.

## Gotchas

- **Open-dataset is async-spawned**, not awaited inline. The handler returns immediately; a background task runs the orchestration and broadcasts when ready. A second open of the same URL during the first import races on the binding map; `open_dataset` re-checks the binding presence under the session lock (via `find_loaded_binding`) and, if it lost the race, drops its duplicate binding/command and rebroadcasts the canonical `DatasetOpened` event instead. The re-check/rebroadcast is in the body of `open_dataset` (dataset_open.rs).
- **Generated coarse cache directories are generation scoped** by the canonical full source-identity digest and source-revision digest, not a workspace dataset id. Reopen can recover the same derived chunks without allowing two source generations to alias.
- **Generated coarse fill is best-effort.** Background work warms coarse chunks, but visible requests and viewer-interest reprioritization drive correctness. Pending chunks surface as generated status messages, not timeouts.
- **Storage compression is detected once at import** by [lucida-store](lucida-store.md)'s `codec::parse_codec_chain` and assumed uniform across levels; the server only consumes the result. If a dataset uses different compression at different LODs, this assumption breaks silently.
- **Persistent state lives in SQLite** (`lucida.db` + `.db-shm` + `.db-wal`). It holds auth state plus workspaces, membership, dataset-source/layer records, saved views, and per-user workspace state. Retired bookmark tables may still exist from the migration ledger but have no runtime reader or writer. `LUCIDA_DB_PATH` configures the path; default is CWD-relative — set an absolute path in production. See [OSS Config Defaults and the LUCIDA_* Env Var Contract](../../gotchas/oss-config-defaults.md).
- **`PRAGMA foreign_keys` is per-connection.** SQLite cascades only fire when this PRAGMA is on. sqlx 0.8 enables it by default through `SqliteConnectOptions`, and the production/recovery constructors set it explicitly so the contract cannot drift with a dependency default. Data rekeys defer checks only inside their transaction; store operations that rely on relationship cleanup still keep tests around deletion behavior.
