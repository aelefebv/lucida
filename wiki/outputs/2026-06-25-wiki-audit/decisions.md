# Decisions (ADR) accuracy audit — 2026-06-25

## Intro

This audit cross-checks every ADR in `wiki/decisions/` (0001–0042 plus `deferred.md`) against the current source tree, which is treated as ground truth. The headline result is reassuring: **no decision is wrong, and no accepted decision has been silently superseded** — every ADR's actual *decision* still holds, and the three ADRs (0024, 0025, 0038) and partial-supersessions (0004) that were overtaken by the proxy→chunk-tier migration already carry accurate `Superseded`/bridge status headers pointing at ADR 0039. What *has* rotted is the supporting detail: stale code anchors (overwhelmingly from ADR 0029's `planning/index.ts` split and the `orchestrator.ts`→`tickCoordinator.ts` rename), a handful of dead file paths, two wrong LOC estimates, one nonexistent function cited as evidence, and a small number of factually incorrect implementation specifics. The list below enumerates every ADR that is not accurately reflected; everything not listed in section (2) holds cleanly.

## 3. Cross-cutting themes

1. **The single biggest source of rot is ADR 0029's planning-module split.** It moved nearly every symbol out of `planning/index.ts` (now re-export-only) into siblings (`emit.ts`, `modes.ts`, `chunks.ts`, `plan.ts`, `config.ts`, `types.ts`, `proxyResidency.ts`). This staled the `planning/index.ts::symbol` anchors in **0023, 0024, 0025, 0026, 0027** at once. The decisions all hold (every symbol is still exported through the barrel); only the cited file homes are wrong. A single sweep re-pointing `planning/index.ts::X` → the owning sibling fixes all five.

2. **The `orchestrator.ts` → `tickCoordinator.ts` rename (ADR 0034) is under-propagated.** Lingering "orchestrator" references / `orchestrator.ts` anchors appear in **0009, 0026, 0028, 0030**. Same global find-replace fixes them.

3. **Render-path file deletions left dangling anchors.** `renderLoop.ts` (as a standalone), `slicePath.ts`, `volumePath.ts` are cited as still-present consumers in **0028** but no longer exist; only `pipeline/renderRadius.ts` remains from that cluster. (Note: `renderLoop.ts`, `slicePath.ts`, `volumePath.ts` *do* still exist as wiring sites cited correctly in 0009/0034 — verify per-anchor; the dangling ones are specifically in 0028's `SceneEpochs` consumer list.)

4. **Post-refactor LOC estimates are the least reliable claims.** **0032** ("~250 lines" vs actual 1230) and **0034** ("~400" vs 711) are flatly wrong; 0034's `uploader.ts` "~250" vs 311 is close. Recommend dropping hard LOC numbers from refactor ADRs or marking them as as-of-landing snapshots.

5. **`dataset_id_for_url` / the URL classifier migrated lucida-core → lucida-content.** The canonical home is now `lucida-content/src/url.rs` (blake3); `lucida-core/src/saved_view.rs:229` is a thin wasm-bindgen re-export. This is correctly captured by ADRs **0042** and **0014**'s amendment, but older cites in **0013** still point at the lucida-core shim (which resolves but is no longer the home) — worth a one-line annotation.

6. **Supersession hygiene is good.** Every overtaken ADR (0024, 0025, 0038, and 0004's partial supersession) carries an accurate `Superseded`/bridge status header pointing at the right successor (0039). No ADR was found silently obsolete. The only status-vs-body inconsistency is **0014**, where the amendment header is correct but the Consequences bullet still describes the pre-amendment `startsWith` classifier.
