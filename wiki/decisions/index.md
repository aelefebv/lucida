# Decisions

Most articles below were originally seeded by reading the code (rationale reconstructed). Where a decision has subsequently been confirmed, refined, or extended via authoritative source material or a maintainer interview, the article notes that.

- [Bounded admission window for an oversubscribed wanted set](0044-bounded-admission-window-for-an-oversubscribed-wanted-set.md) — when the honest wanted set exceeds what the transport can deliver in interactive time, the pending queue splits into a bounded committed window and an ordered backlog that is never dropped (so an at-rest fill still completes); an enqueue stamp comes to mean "admitted", not "first wanted". - [Trace model: phases, runs, and lifecycle rows](0047-trace-model-phases-runs-and-lifecycle-rows.md) — what the pipeline performance monitor records: a **stage is a phase** delimited by an ownership handoff (not a directory — four ADRs have already renamed those directories; thread/process is a separate dimension, lane and tier are attributes), a **run is a labelled interval** in a continuous always-on recording (so an interaction run and a dataset-open run are one object differing only by cause), and the **unit of record is a fixed-width per-chunk lifecycle row** plus per-tick aggregates and point events. The row dissolves the #887-vs-#888 tension: the in-memory model is a table (~32 B/chunk) and Chrome Trace Event JSON is a projection at export (~1.1 kB/chunk), so neither decision has to give. Browser and server keep separate tables joined many-to-one on an outbound-only correlation id (the binary frame has no spare bytes; tier duplication makes the many-to-one routine); a phase earns a timestamp only above the 100 µs clock floor; workers are bracketed from the main thread rather than timestamped, avoiding cross-context clock alignment; overflow truncates the run instead of dropping its start (issues #886/#885; 2026-08-10, accepted)
- [Correlating work across the browser/server boundary](0048-correlating-work-across-the-browser-server-boundary.md) — the browser and server lifecycle tables join on **`rid`**: a required, client-minted, per-connection monotonic `u32` on `ChunkRequest` / `AssetRequest` / `ChunkFetch`, with chunk and asset sharing one counter so `(connection, rid)` is globally unique. Derived identity (`composite_key` + nth occurrence) was rejected as free-but-wrong: timeouts and reconnect desynchronise the two counters exactly under the failures a trace exists to diagnose. Integer over string, and the terse field name, are costed against #888's warm re-open (2,559 chunks, 95 B envelope): `rid` +12% request bytes vs +55% for a UUID string. Dataset-open reuses the existing `request_id` (it is already the parent of its metadata reads) rather than growing a second id, so the exporter carries two join paths. Coalesced rows all copy the first sender's `rid`, which makes the many-to-one join an equi-join and yields the coalescing counter for free. Reaches `ChunkFetch` — where #899's 12-permit source-read wait lives — but not the generated queue. Ships with the server-side table, not before it (issue #890; 2026-08-10, accepted)
- [Unconditional recording under a design budget](0049-unconditional-recording-under-a-design-budget.md) — the monitor of [ADR 0047](0047-trace-model-phases-runs-and-lifecycle-rows.md) records **always, with no opt-out at any scope** — overriding #885's "on by default with an opt-out", because no honest motive for the switch survived (idle emits nothing, so cost is a placebo; the recording never leaves the process, so privacy belongs to export; benchmark determinism is answered by the clock bound instead). Deleting the toggle deletes the whole subtree of scope questions and [ADR 0012](0012-logging-conventions.md)'s module-init caching trap with it. The budget is a **CI-asserted design contract, not a runtime governor** (a governor would make the monitor instrument itself — the perverse case — and make a deterministic cost emergent): ≤100 ns/event, ≤250 µs worst tick, zero steady-state allocation, and cost **flat** in events-per-tick (the #898 failure mode). Retention is an 8 MB resident cap evicting whole completed runs; the **only** degradation is a 2 MB per-run truncation declared as a record with a post-truncation counter — no sampling or coarsening rung, since a silently coarsened trace is the confidently-wrong picture. The observer effect is bounded not by a correction but by the clock: ~100 ns against #897's 100 µs floor is unrepresentable (issues #894/#885; 2026-08-10, accepted)
- [How server-side timings reach the monitor](0050-server-timings-reach-the-monitor.md) — the **browser owns the merged trace**; the server pushes its own rows to the client that caused them as **batched column arrays** on the existing socket (250 ms ticker, 512-row early flush, derived from #899's 82/s remote and 894/s local), with no server-side trace store or endpoint. End-of-run pull is *structurally unavailable* — per [ADR 0048](0048-correlating-work-across-the-browser-server-boundary.md) the server has no idea runs exist — and batching collapses the retention question to one flush window. Clock skew is **avoided rather than corrected**: server rows carry offsets from their own arrival and are placed by **nesting inside the browser-measured bracket**, so the server's clock is never trusted and the leftover is named as a gap. A client sees only its own rows — its own permit wait yes, process-wide aggregates never, since the 12-permit limiter is shared across all sessions. Corrects two things the prior ADRs assumed: **there are two coalescing layers**, so a follower row must keep its hands off the leader's backend-read columns or the trace overstates store load; and a run can **outlive a reconnect**, so the join key gains a connection generation. The server's enum is finer than the browser's because Rust's clock has no 100 µs floor, and gains a slot for the shared-session-mutex lookup that nothing measures today. #891's `lucida-proxy` bullet was a *proxy asset* / network-proxy name collision and is struck (issue #891; 2026-08-10, accepted)
- [The trace driver and the page export seam](0051-the-trace-driver-and-the-page-export-seam.md) — how `lucida trace` drives a headless run and gets the trace out. Overrides #885's preference to extend `lucida debug state`: that command opens a socket to the *server*, computes in the CLI, and declares in its own caveats that it cannot see the browser — there is no transport there to extend. The trace leaves the page by CDP evaluation against **a production page-level export seam**, which is also the shared seam for the second entry point (an agent driving its own browser), so the CLI holds no diagnostic logic. Settling is a **published `quiescent` boolean** (dirty flags clear, no frame in flight, desired detail resident, prefetch excluded) held 500 ms — never inferred from a stalled frame counter, since a finished run and a stuck one both stop drawing; a run that never settles is still emitted, which makes a run's **end reason** required. The CLI fetches **nothing** and holds no join: under [ADR 0050](0050-server-timings-reach-the-monitor.md) the server's rows are already pushed into the page, so the seam returns a merged document and both entry points get the same artifact. The run is written **to a file**, because the browser that held it is killed at teardown. **DPR defaults to 2** (the existing CDP path hardcodes 1, and DPR-1-only verification has hidden defect classes here before), `render=1` stops writing user state, server warmth goes in the header, and a stall exits **zero** unless a gate flag asks otherwise — coverage alone never fails a gate, since 87% of a healthy local open is pre-instrument boot (issues #895/#885; 2026-08-10, accepted)
- [Debug surface dispositions](0052-debug-surface-dispositions.md) — the ten-tab `DebugPanel.tsx` is dismantled: **observation moves to the monitor where it is temporal and to [ADR 0047](0047-trace-model-phases-runs-and-lifecycle-rows.md)'s per-tick aggregate table where it is a count, is deleted where it is neither, and mutation keeps one small dev-only surface** (`DevControls` — planning knobs, the six overlay toggles, and the four session-scoped cache knobs, named for mutation because configuration is only one of its contents). Two corrections drove it: *absorbed* covered a minority of the panel, because the monitor is a timing artifact and the panel is a gauge board, so labelling gauges "absorbed" would delete capability under a label claiming preservation; and the apparent fourth fate — *moved to the agent surface* — dies on transport, since all three CLI diagnostics derive from server/scene state and cannot reach browser residency or CPU-cache state without new wire. The in-viewport overlays survive decoupled (spatial, where the monitor is temporal — Perfetto cannot draw them); Health is deleted because `lucida dataset health` already returns the same `DatasetSourceHealth` bytes, leaving only "Retry binding" to become `lucida dataset retry`; the Logging tab's checkboxes go, since `localStorage.debug` + reload was always the real interface. `debugStats.enabled` is deleted **with** the recorder, not before, because the gate and the gauges are the same lines. Catalog and `ProxyResidencyDebug` are dead by [ADR 0043](0043-superseded-server-surfaces-sunset.md) §C, depended on rather than absorbed (issue #896; 2026-08-10, accepted)
- [Fair-share source-read admission](0053-fair-share-source-read-admission.md) — the concurrent-source-read cap keeps **one process-global bound** (the link to the object store is shared, and per-client caps would let *k* clients drive *k·n* streams) but **admission becomes per-reader, least-in-flight-first**, so one client opening a large collection can no longer own the store until its burst drains; it stays work-conserving, so a lone reader still gets the whole cap. Coalesced proxy generation and other non-client reads share one background class rather than being charged to an arbitrary client. The value is **measured, not defaulted**: sweeping concurrency against the real remote collection shows throughput plateauing at **16** with aggregate bandwidth flattening alongside it, so past the knee **the link is the ceiling, not the cap** — and the extra streams still cost, doubling body-transfer p50 by 24 and *reducing* throughput by 48. This corrects [#900](https://github.com/aelefebv/lucida/issues/900)'s closing claim that the semaphore was the ~82 reads/s ceiling: 12 sat just below the plateau (worth ~12%), and raising it further makes things worse. Live re-measurement halves permit wait p50 (190 → 101 ms) while TTFB stays flat and part of the saving reappears in body transfer, exactly as the sweep predicts (issue #901; 2026-08-10, accepted)
- [Unwritten levels are named, not hidden](0054-unwritten-levels-are-named-not-hidden.md) — a pyramid level a store declares but never wrote chunks for reads as `fill_value`, which is legal Zarr and renders as an all-zero image; lucida now detects it at import, **keeps** it, and reports it. Detection is **relative, not absolute**: the origin chunk of every level is probed concurrently (one HEAD each, one round trip, once per multiscale geometry rather than per member) and a level is only accused when its origin is absent *while the origin chunk of some level it spatially contains is present*. The containment test is load-bearing — origin chunks all start at the same corner but span different amounts of source space (2048 vs 512 units in #904), so only "big one missing, small one inside it populated" is a contradiction; the reverse is ordinary sparse data. Absence everywhere (a metadata-only store, or most of this repo's fixtures) stays silent, and a single-level pyramid has no witness. A `list`-based check was rejected because it needs `storage.objects.list`, which readers granted only `objects.get` lack; dropping the level was rejected because a level index doubles as its on-disk directory name, so removing one misaligns every later chunk key — trading a visible wrong reading for an invisible one. Health must **move**, not merely gain a line: `Degraded`, since the measured failure was every surface reporting `healthy` over a black default view with a degenerate `0–0` auto-contrast window. Picks up the consequence [ADR 0045](0045-tolerant-ome-attribute-placement.md) explicitly deferred, and fixes a pre-existing `combine_health` asymmetry that dropped a `Degraded` in the left position (issue #904; 2026-08-11, accepted)
- [The storage backend is selected by a connection string](0055-storage-backend-selected-by-connection-string.md) — one **storage backend** owns the database connection, runs the migrations, and hands out all six stores; the scheme of `LUCIDA_DB_URL` picks it with a `match` at startup, in the shape [ADR 0017](0017-configurable-from-day-one-for-oss-release.md) set for auth providers. Supersedes [ADR 0015](0015-server-stored-bookmarks-and-auth-seam.md) on one point only: its rejection of Postgres as "overkill for the deployment scale" was conditional on one process on one machine, and lucida also runs on container platforms, where the filesystem is ephemeral unless someone attaches a volume and a single-writer file cannot serve a second replica at all. SQLite stays the default and stays first-class. The real defect was ownership, not the database: `SqliteSessionStore` opened the pool and exposed it so the other five stores could borrow it, which put a SQLite type in a public signature nowhere near SQLite and left no place for a second backend to plug in. `LUCIDA_DB_PATH` is deleted rather than aliased — a breaking change under ADR 0017's env-var contract, taken because lucida is pre-1.0 and a bare path in the new variable fails startup instead of silently opening the wrong database. Connection strings are redacted wherever printed, a no-op for SQLite and the reason no later network backend leaks a password into a log (2026-09-02, accepted)
- [Store behavior is a conformance suite](0056-store-behavior-is-a-conformance-suite.md) — each of the six store traits owns one suite of observable-behavior cases, parameterized over an implementation and run against every implementation of that trait; a case may assert only what a caller sees through the trait, never a table, a column, a query plan, or which store is running. Four of the five paired traits were tested twice over, once per implementation, each test asserting what its own store happened to do, so no divergence could be seen; the bookmark store already ran a few generic helpers against both, and its divergence survived in the one thing they left unpinned. The first run found three, across four traits — a reused primary key overwrote in memory and errored in SQL, a second approval of a CLI token authorization re-pointed it in memory and was ignored in SQL, and a bookmark's dataset attachments came back in three different orders depending on which store and which method. Each resolved toward the SQL semantics, not because SQLite is production but because in each pair it is the behavior that **refuses** where the other quietly replaces. Attachment ordering is the exception, where neither store was right: caller order cannot survive a schema with no column to keep it in, attachments are a set, so both create paths now return the URL order both read paths already did. Makes [ADR 0055](0055-storage-backend-selected-by-connection-string.md)'s "adding a backend is a bounded change" true of behavior and not just of compilation (2026-09-03, accepted)
- [One baseline schema, with honest column types](0057-one-baseline-schema-with-honest-column-types.md) — thirteen incremental migrations collapse into one **baseline** that creates every table, index, and constraint; the old files are deleted rather than archived, and no older database upgrades into it. Available only because no deployment holds data, and taken because reconstructing a schema from an append-only history is the largest piece of writing the second backend [ADR 0055](0055-storage-backend-selected-by-connection-string.md) made room for — `workspace_saved_views` was spread across three files. Four typing inconsistencies that SQLite's loose typing had hidden are resolved the same way in every table: a timestamp is `TEXT` holding RFC 3339 in UTC and maps to `DateTime<Utc>` (not `TIMESTAMP`, whose NUMERIC affinity converts anything that looks like a number, and not an epoch integer, which sorts no better and cannot be read in a shell); a JSON payload is `TEXT` with a `json_valid` check, the strongest claim SQLite can make where a `_json` suffix on the name was the only claim before; `seq` and `sort_order` are `BIGINT`, which is the same storage in SQLite and four bytes rather than eight in several other engines; and every parent-child edge declares its own `ON DELETE`, with foreign-key enforcement set explicitly on each connection, so the transaction-scoped cascades written by hand in Rust are gone. No table and no column is renamed, and the [ADR 0056](0056-store-behavior-is-a-conformance-suite.md) suites pass unchanged, because none of this is visible through a store trait (2026-09-03, accepted)
