# WASM Rebuild After Rust Changes

## The footgun

Touching [[lucida-core]] Rust source doesn't automatically reflect in the running web client. Vite's hot-reload watches `lucida-web/src/`; the WASM bundle is generated into `lucida-core/pkg/` (committed as a build artifact) and only regenerated by `npm run build:wasm`. The web app imports it via the `"lucida-core": "file:../lucida-core/pkg"` package alias in `lucida-web/package.json`.

Symptoms:

- Compiles cleanly: `cargo test -p lucida-core` passes.
- Browser shows old behavior. New tests pass; the visible app doesn't reflect the change.
- Worse: the JS-side TypeScript types in `lucida-core/pkg/lucida_core.d.ts` are stale, so a new method you added in Rust **isn't visible to TS** until you rebuild.

## The dev loop

For a Rust change in [[lucida-core]]:

```
cargo test -p lucida-core
cd lucida-web && npm run build:wasm
```

Then refresh the browser (Vite picks up the new `lucida-core/pkg/` files automatically). Restart `npm run dev` only if Vite's dependency cache misses the change.

For pure-TS changes in [[lucida-web]], no rebuild is needed — Vite hot-reloads.

## Why we commit the WASM bundle

Two reasons (inferred):

1. **Onboarding speed**: a fresh clone runs the web app without needing the Rust toolchain. `cd lucida-web && npm install && npm run dev` is enough.
2. **CI determinism**: the bundled WASM is what the test browser uses; rebuilding in CI would add minutes and a wasm-toolchain dependency.

The cost is the manual rebuild step in the dev loop, mitigated by it being scriptable (`npm run build:wasm` does the right thing).

## What to do

- **Add `npm run build:wasm` to your post-Rust-edit muscle memory.** It's the second half of every Rust change.
- **If TypeScript reports an unknown WASM method**, your `lucida-core/pkg/lucida_core.d.ts` is stale — rebuild.
- **For Python (`lucida-py`)**: the equivalent is `cd lucida-py && maturin develop` after Rust changes. README documents this.
- **Don't commit a half-rebuilt `lucida-core/pkg/` directory.** If you're unsure, regenerate locally and verify the diff is consistent.
