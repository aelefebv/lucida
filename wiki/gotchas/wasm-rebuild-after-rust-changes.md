# WASM Rebuild After Rust Changes

## The footgun

Touching [[lucida-core]] Rust source doesn't automatically reflect in the running web client. Vite's hot-reload watches `lucida-web/src/`; the WASM bundle is generated into `lucida-core/pkg/` (which is gitignored — see below — not committed) and only regenerated by `pnpm run build:wasm`. The web app imports it via the `"lucida-core": "file:../lucida-core/pkg"` package alias in `lucida-web/package.json`.

Symptoms:

- Compiles cleanly: `cargo test -p lucida-core` passes.
- Browser shows old behavior. New tests pass; the visible app doesn't reflect the change.
- Worse: the JS-side TypeScript types in `lucida-core/pkg/lucida_core.d.ts` are stale, so a new method you added in Rust **isn't visible to TS** until you rebuild.

## The dev loop

The canonical loop is `./scripts/dev.sh`. It brings everything up to date in one command and **auto-rebuilds the WASM pkg only when a `lucida-*` Rust source actually changed** — it content-hashes every workspace `.rs` source + `Cargo.toml` into `lucida-core/pkg/.dev-src-hash` and rebuilds only on a mismatch. The hash is over bytes, not mtimes, precisely so a `git checkout` that bumps mtimes doesn't trigger a needless rebuild. It then `pnpm install --force`s the web deps (to refresh the `file:` pkg copy) and starts both servers. Pass `--wasm` to force a rebuild.

The manual fallback, for an ad-hoc rebuild without the full loop:

```
cargo test -p lucida-core
cd lucida-web && pnpm run build:wasm
```

`build:wasm` runs `wasm-pack build --target web --out-dir pkg`. After it, refresh the browser (Vite picks up the new `lucida-core/pkg/` files automatically). Restart `pnpm run dev` (or pass Vite `--force`) only if Vite's optimized-dep cache misses the change.

For pure-TS changes in [[lucida-web]], no rebuild is needed — Vite hot-reloads.

## pkg/ is generated, not committed

`lucida-core/pkg/` is gitignored at three levels (root `.gitignore`, `lucida-core/.gitignore`, and `lucida-core/pkg/.gitignore` = `*`), so `git ls-files lucida-core/pkg/` is empty. A fresh clone therefore **cannot** run the web app without the Rust/wasm toolchain — `README.md` lists `wasm-pack` as a prerequisite and the pkg must be built on first run (`./scripts/dev.sh` does this for you).

One sharp edge of the content-hash: it only watches `.rs` sources and `Cargo.toml`. Changing the `wasm-pack` invocation or build flags themselves won't invalidate the hash, so use `--wasm` (or delete `lucida-core/pkg/.dev-src-hash`) after a toolchain/flag change.

## What to do

- **Prefer `./scripts/dev.sh`** — it folds the WASM rebuild into the normal loop, so it's no longer a step you can forget.
- **If TypeScript reports an unknown WASM method**, your `lucida-core/pkg/lucida_core.d.ts` is stale — rebuild (`pnpm run build:wasm` or `./scripts/dev.sh --wasm`).
- **For Python (`lucida-py`)**: the equivalent is `cd lucida-py && maturin develop` after Rust changes. README documents this.
